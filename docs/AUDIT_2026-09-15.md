# Audit du site — 15 septembre 2026

## Périmètre

Parcours publics : accueil, univers, personnages, joueurs, clan Nakamura, Manoir de Sétia, chronologie, journal, galerie, textes RP, Culture, Aether et connexion. Visite des 13 pages à 375 et 1440 pixels : pas d’erreur JavaScript ni de débordement horizontal sur ces parcours avant correction. Les tests supplémentaires reproduisent des erreurs réseau et des données créées par les joueurs.

Les actions de publication/modification/suppression et les contrôles de propriétaires sont testés avec des données isolées. Aucun contenu de test n’est publié sur le site réel. Les modifications locales de personnages et de configuration déjà présentes restent hors du commit.

## Corrections

| Problème constaté | Correction |
| --- | --- |
| Un lieu créé par un joueur redirigeait avant la réponse serveur | État de chargement explicite et maintien de la fiche jusqu’à la réponse |
| Une fiche précédente ou statique pouvait rester visible après changement de route ou réponse 404 | Résultats liés à l’identifiant de route ; un 404 retire le contenu de secours pour les clans, lieux et articles |
| Galerie, mots-clés et références du Journal ignoraient les nouvelles données des joueurs | Utilisation des collections publiques actualisées ; filtrage des brouillons dans la collecte des images |
| Un mot-clé contenant `%` pouvait provoquer une exception | Suppression du second décodage des paramètres déjà décodés par le routeur |
| Culture pouvait planter si un proxy renvoyait du HTML ou une liste invalide | Validation des réponses, message explicite et bouton Réessayer ; isolation des résultats par route |
| Avatar et couverture externes cassés | Remplacement visuel lisible pour avatars, couvertures de liste et visionneuse, sans changer les sources enregistrées |
| La galerie agrandie laissait le clavier naviguer derrière la fenêtre | Focus initial, boucle Tab, Échap, restauration du focus et du défilement ; fermeture en suivant la source |
| La galerie actualisée pouvait garder un index d’image invalide | Sélection par source d’image plutôt que par index |
| Univers n’était pas indiqué actif dans ses sous-rubriques | Mise en évidence du groupe, tout en conservant un seul sous-lien actif |
| Une nouvelle page pouvait s’ouvrir à la position de défilement précédente | Retour en haut pour les nouvelles pages, sans forcer les ancres, filtres ni retours dans l’historique |
| Les archives RP n’affichaient pas leur texte | Lecture dépliable avec le rendu Markdown existant |
| Accès clavier et crédit d’image peu lisibles | Lien d’évitement vers le contenu ; contraste des crédits dans la visionneuse sombre |

## Vérification

- `npm test` : 30 tests réussis, dont sessions, propriétaires, permissions, brouillons, Culture et nettoyage des contenus.
- `npm run build` : compilation réussie.
- `npm run lint` : aucune erreur ; avertissement Fast Refresh préexistant dans PlayerCard.
- `node scripts/test-site-audit-browser.mjs` (Vite sur 5182) : panne Culture/réessai, chargement lent d’un lieu, 404 des lieux et clans, mots-clés contenant %, références actualisées, galerie, image manquante, focus clavier et défilement.
- `node scripts/test-culture-browser.mjs` : publication, modification, suppression, filtres, hashtags et vues responsive dans trois thèmes.
- Les API compte, administration et utilisateurs refusent les accès anonymes en production (401).

## Points restant dépendants de services ou contenus externes

- Deux liens Discord observés ne chargent plus : avatar sur accueil/joueurs et couverture d’un article du Journal. Les remplacements visuels évitent l’icône d’image cassée ; ils ne restaurent pas les originaux. Remplacer ces liens par des URLs durables ou réimporter les images originales une fois le stockage disponible.
- Le binding `WOLTAR_MEDIA` est absent de la configuration de déploiement actuelle et R2 n’est pas activé dans le compte Cloudflare (constaté lors du déploiement précédent). Les boutons d’upload existants ne peuvent donc pas stocker de nouveaux fichiers en production ; les URLs d’images restent utilisables. Aucune activation de service ou modification de facturation n’a été effectuée pendant cet audit.
- Vite signale toujours un bundle principal supérieur à 500 kB. Cela n’empêche pas la compilation ; une optimisation dédiée du découpage des pages peut réduire le chargement initial.

Cet audit couvre les parcours et scénarios ci-dessus, pas un test d’intrusion exhaustif ni une validation de tous les contenus privés de chaque compte.
